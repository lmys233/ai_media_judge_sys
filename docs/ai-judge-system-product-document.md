# AI 智能审核系统 - 产品文档

## 1. 产品概述

### 1.1 产品定位

AI 智能审核系统是一个面向 UGC（用户生成内容）平台的多模态内容审核解决方案。系统能够自动检测文本、图片、视频中的违规内容（色情、暴力、辱骂、政治敏感等），支持 AI 自动审核与人工复核相结合的工作流，提供从内容接入、智能分析、决策路由到结果反馈的全链路服务。

### 1.2 适用场景

- 社交平台用户发布内容的实时审核
- 直播平台弹幕/评论过滤
- 社区论坛帖子自动审核
- 电商平台商品图片/描述审核
- 视频平台上传内容审核
- 即时通讯消息内容过滤

### 1.3 核心能力

| 能力 | 说明 |
|------|------|
| **文本审核** | NB 朴素贝叶斯快速打标 + 文本脱敏重写 + 向量检索 + LLM 判定 |
| **图片审核** | CLIP Zero-shot 快速打标 + VL 描述生成 + 向量检索 + VL 判定 |
| **视频审核** | 关键帧提取 + 逐帧 CLIP 打标 + 帧汇总 + VL 描述 + 向量检索 + LLM 判定 |
| **多智能体复核** | 1 个 ReAct 决策者 + 2 个 CoT 辅助者协同复核，具备自适应纠错机制 |
| **置信度路由** | 三层置信度路由：自动通过（>=0.8）/ 多智能体复核（0.4-0.8）/ 人工审核（<0.4） |
| **主动学习** | AI 审核结果自动入库，持续扩充训练语料和向量库，形成数据飞轮 |
| **多标签检测** | 单条内容可同时检出多种违规类型，并提供各自置信度和证据 |

## 3. 核心工作流

### 3.1 文本审核流程

```
原始文本
    │
    ▼
┌──────────────────────┐
│ 1. NB 朴素贝叶斯多标签 │  ← 加载预训练模型 / 关键词规则
│    快速预打标         │     → 输出: [abuse(0.85), violence(0.35)]
└──────────┬───────────┘
           ▼
┌──────────────────────┐
│ 2. 文本脱敏重写       │  ← 关键词替换 + LLM 语义改写
│    · 规则替换         │     → 脱敏后的语义等价文本
│    · LLM 语义去敏感化 │
└──────────┬───────────┘
           ▼
┌──────────────────────┐
│ 3. 向量检索           │  ← CLIP 文本编码 → Milvus HNSW 检索
│    · 构建特征向量      │     + Reranker 排序
│    · 混合检索 + 重排序 │     → Top-K 相似案例
└──────────┬───────────┘
           ▼
┌──────────────────────┐
│ 4. 历史审核案例补齐    │  ← 调用 Java 后端 batch 接口
│    · 批量获取案例详情  │     补充 review_reason / aiResult
└──────────┬───────────┘
           ▼
┌──────────────────────┐
│ 5. LLM 判定          │  ← 构造 Prompt (原文 + 相似案例)
│    · 多标签检测       │     → 结构化 JSON 输出
│    · 置信度 + 证据    │     → final_label + violation_details[]
└──────────┬───────────┘
           ▼
┌───────────────────────────────────────────────────┐
│ 6. 三层置信度路由                                  │
│                                                   │
│   confidence >= 0.8  ───→ 自动通过/拒绝            │
│                              ├─ 存入 Milvus       │
│                              ├─ 追加 NB 语料      │
│                              └─ 回传审核结果       │
│                                                   │
│   0.4 <= confidence < 0.8 ─→ 多智能体复核          │
│                              ├─ ReAct 决策者       │
│                              ├─ CoT 逻辑辅助       │
│                              ├─ CoT 证据辅助       │
│                              └─ Meta 监督器        │
│                                  ├─ 通过 → 自动    │
│                                  └─ 失败 → 人工    │
│                                                   │
│   confidence < 0.4  ────→ 人工审核队列             │
└────────────────────────────────────────────────── ┘
```

## 4. 功能模块说明

### 4.1 预打标引擎 (PreLabel)

| 模块 | 文件 | 技术 | 功能 |
|------|------|------|------|
| 文本分类器 | `text_nb.py` | 朴素贝叶斯 (sklearn) + 关键词规则 | 多标签预测：hard 关键词命中、soft 关键词加分、NB 概率预测 |
| 图片 CLIP 分类器 | `image_quick_label.py` | CLIP Zero-shot 图文相似度 | 多标签分类，预定义 5 类违规文本描述，阈值 > 0.25 |
| 图片 MobileNet | `image_mobilenet.py` | MobileNet 图像分类 | 传统图像分类器（兼容旧链路） |
| 视频帧汇总 | `video_summary.py` | 帧级结果汇总 | 多帧标签和分数聚合 |
| 预打标管道 | `pipeline.py` | 策略模式 | 根据媒体类型路由到对应的打标器 |

**NB 分类器核心特性：**
- 支持 5 类违规：normal / abuse / violence / porn / politics
- 分层规则引擎：hard 关键词 → soft 关键词 → NB 概率
- 训练语料热加载：检测到文件变化自动重训
- 内置 10 条种子样本，支持增量追加
- 训练文件持久化到磁盘，重启时免重训 (hash 校验)

**CLIP 快速打标：**
- 使用 5 类违规的英文文本描述计算图文相似度
- 阈值 0.25 做多标签分类，宽进严出，高召回。
- 各类型风险基础分：ABUSE=0.5, VIOLENCE=0.6, PORN=0.7, POLITICS=0.5, OTHER=0.3

### 4.2 特征工程 (Feature)

| 模块 | 文件 | 技术 | 功能 |
|------|------|------|------|
| 文本脱敏 | `desensitize.py` | 关键词替换 + LLM 语义重写 | 规则替换敏感词，LLM 做语义等价重写供 RAG 入库 |
| 图片描述 | `image_desensitize.py` | Qwen-VL 多模态 | 生成：简短中性描述 + 详细证据描述 |
| 文本编码器 | `embedder.py` | CLIP Text / OpenAI / Hash | 统一 512/768 维语义空间 |
| 图片编码器 | `image_embedder.py` | CLIP ViT-B/16 | 图像嵌入 + 跨模态检索 |

**脱敏处理器分层设计：**
1. **Hard 规则层**：正则匹配预定义敏感词表，替换为 `[违规言语]` / `[暴力威胁]` 等占位符
2. **Soft 规则层**：从 YAML 配置文件加载可扩展关键词
3. **LLM 语义层**：使用定制提示词做语义等价重写，保留原文攻击性和意图但不含违禁词
4. **自动降级**：LLM 不可用时自动回退到规则层

### 4.3 向量检索 (Retrieval)

| 组件 | 技术 | 说明 |
|------|------|------|
| 向量数据库 | Milvus 2.6 | Collection: `audit_cases` |
| 索引 | HNSW (M=16, efConstruction=256) | 余弦距离度量 |
| 编码维度 | 512 (ViT-B/16) | CLIP 统一语义空间 |
| 标量索引 | STL_SORT (risk_score) | 加速标量过滤 |
| 重排序 | `SimpleReranker` | 4 信号综合排序 |


**重排序：**
 SimpleReranker.rerank() 用 NB 的输出作为多信号加权的参照：
  - **violation_match**：检索结果的违规类型是否命中 NB 预测的违规类型 → 命中 +1.0 分
  - **risk_closeness**：检索结果的 risk_score 与 NB 输出的 risk_score_pre 的接近度 → 权重 0.3
  - **vector_score** × 0.6（余弦相似度）+ human_bonus（人工验证过的案例额外加分）

**搜索策略：**
- **优先混合检索**：媒体类型 OR 违规类型 → 高召回
- **降级纯向量搜索**：混合检索结果 < 3 条时自动降级
- **最低分数阈值**：0.4 (CLIP 跨模态相关度门限)
- **Reranker 多信号**：违规类型匹配 + 人工验证加分 + 向量相似度 ×0.6 + 风险分接近度 ×0.3

### 4.4 审核判定 (Reasoning)

| 模块 | 技术 | 功能 |
|------|------|------|
| 文本判定器 | LangChain + LLM | 基于原文 + 相似案例做多标签判定 |
| 图片判定器 | Qwen-VL-Max | 多模态输入直接审核图片 |
| 多智能体复核 | ReAct + CoT | 中置信度场景三智能体协同复核 |
| 遗留复核器 | ReActReviewer | 向后兼容的旧版复核逻辑 |

**LLM 判定器输入：**
- 脱敏后的原文/图片描述
- 检索到的 Top-5 相似案例（含违规类型、风险分、描述、审核理由）
- 元数据（违规候选类型、模型版本等）

**输出结构：**
```json
{
  "final_label": "porn",
  "confidence": 0.85,
  "reason": "图片内容包含明显的性暗示元素",
  "violation_details": [
    {"violation_type": "porn", "confidence": 0.85, "evidence": ["裸露", "挑逗姿态"], "reason": "穿着暴露，姿态挑逗"}
  ]
}
```

### 4.5 多智能体复核系统

**核心思想：** 当 LLM 初次判定置信度处于中区间 (0.4-0.8) 时，引入多智能体协同复核以提高准确率。

**架构：**
```
┌─────────────────────────────────────────────────┐
│                  MetaReviewSupervisor           │
│  ┌─────────────┐  ┌──────────┐  ┌──────────┐    │
│  │ ReAct决策者  │  │ CoT逻辑  │  │ CoT证据  │    │
│  │ (决策者)     │  │ 辅助者   │  │ 辅助者    │    │
│  └──────┬──────┘  └────┬─────┘  └────┬─────┘    │
│         │              │             │          │
│         └──────────────┴─────────────┘          │
│                        │                        │
│         Supervisor 协调轮次、跟踪错误、决定路由    │
└─────────────────────────────────────────────────┘
```

**复核流程：**
1. **决策者**分析原始结论和案例，输出 thinking_chain（至少 2 步推理）
2. **逻辑辅助者**检查 thinking_chain 的逻辑漏洞
3. **证据辅助者**检查证据充分性
4. 发现质疑 → 反馈给决策者 → **rerethink**（多轮迭代）
5. 停止条件：累计错误 >= 3 或达到最大轮次 (3)

**自适应路由：**
- 复核置信度 >= 0.65 → 自动通过/拒绝 (auto_pass)
- 复核置信度 < 0.65 或错误 >= 3 → 人工队列 (dlq_manual)

### 4.6 决策路由 (Decision Gateway)

| 层级 | 置信度区间 | 行为 | 说明 |
|------|-----------|------|------|
| Auto | >= 0.8 | 自动通过/拒绝 | 回传结果 + 存入 Milvus |
| Review | [0.4, 0.8) | 多智能体复核 | 复核通过 ≥ 0.65 → 自动；否则 → 人工 |
| Manual | < 0.4 | 直接送人工 | RabbitMQ audit.manual 队列 |

### 4.7 消息队列 (RabbitMQ)

| 队列 | 用途 | 消费方 |
|------|------|--------|
| `audit.task` | 审核任务 | AI 审核引擎 (带死信队列和重试) |
| `audit.task.dlq` | 死信队列 | 重试耗尽的任务 |
| `audit.failure` | 失败队列 | 三次重试都失败的任务 |
| `audit.manual` | 人工审核任务 | 审核管理平台 |
| `audit.manual.result` | 人工审核结果回传 | AI 审核引擎 |
| `audit.manual.case` | 人工案例同步 | 案例同步 Worker |
| `audit.result` | AI 审核结果 | 审核管理平台 |

**重试机制：**
- 最大重试 3 次
- 内存去重 (InMemoryDedupeStore，TTL=600s)
- NACK 不确认 + 重新入队机制
- 3 次耗尽 → failure 队列 + 通知平台

### 4.8 违规分类体系

基于 **AEGIS 2.0** 论文的违规分类法，适配中文审核场景：

| 顶层分类 | 映射子类 |
|---------|---------|
| normal | safe |
| abuse | hate_identity, harassment, profanity, fraud_deception |
| violence | violence, threat, illegal_weapons, criminal_planning_confession, suicide_self_harm |
| porn | sexual, sexual_minor |
| politics | political_misinfo_conspiracy, gov_decision_making |
| other | pii_privacy, controlled_substances, illegal_activity, malware_manipulation, unauthorized_advice, immoral_unethical, copyright_trademark_plagiarism, other_high_risk |

每个子类含内置中文引导关键词（如：porn → ["约炮", "裸照", "情色", "成人视频"]）。

### 4.9 典型纠偏案例库 (Reference Error Memory) `[TBD/待实现]`

**定位：** 当人工审核纠正 AI 误判时，将具有代表性的纠偏案例提炼为全局警示，注入 LLM 判定 Prompt，避免同类错误反复发生。它与向量检索互补——向量检索靠内容相似度召回，纠偏案例靠「错误模式」匹配，不受内容关联性限制。

**工作流：**

```
人工审核纠正 AI 误判
    │
    ▼
审核员勾选「标记为典型纠偏案例」
    │  + 填写纠偏摘要（选填，LLM 自动生成兜底）
    ▼
写入 error_memory.jsonl（累积原始记录）
    │
    ▼
管理员定期筛选审核（按 hit_count + recency 排序）
    │  - 去重合并（同一模式只保留一条）
    │  - 修正/精炼摘要表述
    │  - 标注生效时间
    ▼
确认后写入 reference_errors.yaml
    │
    ▼
Worker 启动时加载 → 按 media_type 筛选
    │  → 取 Top-5 注入 LLM 判定 Prompt
```

**维护原则：**

- **半自动化**：记录自动采集，入库筛选由管理员手工确认，不走自动化管道
- **精简化**：不超过 20 条，按 hit_count 和时效性排序，超出容量淘汰最旧条目
- **摘要精炼**：每条控制在 30 字内，清晰描述「什么场景 → 误判成什么 → 正确结果」
- **可过期**：支持 `effective_until` 字段，临时活动相关模式到期自动失效

**与现有闭环的关系：**

| 闭环 | 更新方式 | 生效速度 | 覆盖范围 |
|------|---------|---------|---------|
| NB 增量重训练 | 自动 | 慢（小时级） | 文本预打标 |
| Milvus 案例库扩充 | 自动 | 中（分钟级） | 相似内容检索 |
| 纠偏案例库 | 半自动 | 快（即时） | 全局策略调整 |

三者构成递进的三层进化机制：参数级 → 记忆级 → 策略级。

## 5. Worker 模式

系统所有功能以 **Worker** 形式运行，通过命令行启动不同的 Worker：

```bash
# AI 自动审核 Worker（核心）
python -m src.app --worker ai-auto --llm-provider qwen --llm-api-key <key>

# 人工案例同步 Worker
python -m src.app --worker manual_case

# 人工复核结果处理 Worker
python -m src.app --worker manual_result

# 完整审核引擎 Worker（含媒体解析）
python -m src.app --worker task
```

支持所有 LLM 参数通过命令行覆盖（provider / api_key / model / base_url）。

## 7. 数据流闭环

```
                         ┌──────────────┐
                         │  外部业务方    │
                         │  (发审核请求)  │
                         └──────┬───────┘
                                │
                                ▼
┌────────────────────────────────────────────────────────────────────┐
│                           AI 审核引擎                                │
│                                                                     │
│  审核结果 ───→ audit.result 队列 ──→ 业务方回传                       │
│                                                                     │
│  高置信度结果 ──→ Milvus 入库 ──→ 向量库扩充 ──→ 提升后续检索覆盖率     │
│                                                                     │
│  AI 判定结果 ──→ NB 训练语料追加 ──→ 增量重训练 ──→ 提升打标准确率      │
│                                                                     │
│  人工审核结果 ──→ Milvus (human_verified) ──→ 黄金案例库               │
│               ──→ NB (verified=true) ──→ 重训练                      │
└────────────────────────────────────────────────────────────────────┘
```

**数据飞轮效应：**
1. AI 高置信度结果 → 入库 → 更多历史案例 → 检索匹配度提升
2. AI 审核样本 → NB 增量训练 → 预打标准确率提升
3. 人工审核黄金数据 → 向量库 + 训练语料 → 质量最高
4. 冷启动阶段：弱标签策略 (阈值 0.9) 主动入库覆盖

## 10. 质量属性

### 10.1 可用性
- 所有 Worker 支持优雅关闭 (SIGINT/SIGTERM handler)
- RabbitMQ 持久化队列 + 死信队列 + 重试机制
- 审核结果发送在生产者侧有重连和重试逻辑 (3 次)

### 10.2 可扩展性
- Worker 模式：不同职责独立部署，可各自扩缩容
- Milvus 分布式架构：支持横向扩展
- 去中心化：审核引擎无状态，依赖消息队列分发

### 10.3 可维护性
- 所有组件降级路径清晰：LLM 不可用 → 规则引擎 → 默认值
- 模块化设计：预打标、脱敏、检索、判定均可独立替换
- 配置热加载：关键词规则修改后自动生效（基于 mtime 检测）

### 10.4 安全性
- 所有敏感内容脱敏后存储和检索
- 审核理由不输出原始敏感词
- API 密钥通过环境变量管理，不硬编码

## 11. 已知限制与改进方向

### 11.1 当前限制
- `InMemoryDedupeStore` 生产环境应替换为 Redis
- CLIP 模型需 CPU/GPU 资源，低配机器推理较慢
- NB 分类器使用 10 条种子样本，需要更多标注数据提升效果
- 视频审核串行处理帧，大视频耗时较长

### 11.2 推荐改进
1. **在线学习**：接入反馈流，实现实时策略调优
2. **多语言支持**：扩展分类体系覆盖英文、东南亚语言
3. **异步视频处理**：帧级并行处理 + 流式审核
4. **API 网关接入**：标准化 REST/gRPC 接口替代消息队列直连
5. **A/B 测试框架**：多模型并行审核，对比效果
6. **可解释性报告**：生成完整的审核推理报告（含决策链可视化）
7. **典型纠偏案例库** `[TBD]`：实现 4.9 节设计的半自动纠偏记忆系统，包括人工标注、管理员筛选入库、Prompt 注入、去重与淘汰机制
8. **NB-Hard 关键词优先级自适应** `[TBD]`：当前 hard 关键词永久短路 NB 路径（命中 hard 则 NB 不参与判定）。应引入 NB 置信度门限机制——当 NB 训练量达标且置信度 > 阈值（如 0.95）时，允许 NB 覆盖 hard 判定结果，避免 hard 关键词在 NB 充分训练后仍永久占主导
